## Open findings without a plan

Confirmed by reading the code, not yet planned. Each needs a decision first.

- **Security headers**: no `frame-ancestors` / `X-Frame-Options`,
  `X-Content-Type-Options` or `Referrer-Policy` on any response
  (`public/_headers`, `next.config.ts`). The signed-in profile and upgrade
  pages can be framed.
- **Unbounded profile fields**: Firestore rules accept any string for user
  `name` and `avatarUrl` and analysis `title` (`firebase/firestore.rules`,
  `isValidPublicOwner`, `isUserProfileUpdateOnly`). `avatarUrl` is rendered
  as an image to other users on public analyses.
- **OG image slot**: `firebase/storage.rules` lets any signed-in user create
  the OG image for an analysis id that has none yet; the Firestore document
  is committed before the image upload
  (`src/features/log-analysis/firebase/mutations.ts`).
- **First sign-in with two tabs**: both tabs try to create the user document;
  the loser is denied by the rules and signs the user out
  (`src/features/account/firebase/accountStore.ts:45-91`).
- **Analysis detail page**: a signed-out visitor to a private analysis and a
  visitor to a missing one get the same "not found" screen, because the rules
  deny both identically. Whether to offer sign-in there is a copy decision.
- **Profile sync while analyses are loading**: `useProfileMutations` reads
  `myAnalysesAtom`, which is an empty list while the user's analyses are
  loading or failed to load, so a name or avatar change in that window
  updates `users` only and leaves the owner copies on saved analyses stale
  until the next profile change. Needs a decision on what the UI shows when
  the update is refused.
- **Service worker**: `public/sw.js` clones responses after returning them
  (runtime caching likely never happens) and uses one constant cache name.
  Needs a browser check before changing; it ships to every installed client.
- **Deploy script**: `scripts/deploy.mjs` verifies inherited server secrets
  but not the `NEXT_PUBLIC_*` values baked into the client bundle.
- **`package.json` scripts `upload` and `firebase:deploy:prod`**: both reach
  production without the safeguards of `pnpm deploy` and the CI rules deploy.
- **Reduced motion and screen readers**: dice results animate under
  `prefers-reduced-motion` and are not announced (`SimpleDiceOutput.tsx`,
  `DiceOutput.tsx`), contrary to `docs/ui-style-guide.md`.
- **Tests that contradict `docs/testing.md`**: `CcfoliaEditor.test.tsx`,
  `accountStore.test.tsx` and `stripe/server/app.test.ts` mock internal
  modules without a stated reason.

## Findings considered and rejected

- `Object.groupBy` instead of `src/shared/lib/groupBy.ts`: needs Safari 17.4,
  above the supported floor implied by `vite.config.ts` (`safari15`).
- Missing `event.id` de-duplication on Stripe webhooks: handlers re-fetch the
  subscription and converge; duplicates only repeat a notification. A TODO in
  `app.ts` already records the constraint.
- 30-day retention of old client assets and fail-closed deploy: documented
  decisions in `docs/workflow.md`.
- Client-visible feedback Discord webhook (`src/shared/lib/webhook.ts`):
  intentional; it only accepts feedback posts.
- Hard-coded Sentry DSN (`src/shared/lib/sentryClient.ts`): public by design.
- A discriminated union for the saved-characters list, toast store, game-system
  loader, save-operation feedback and public-list pagination: already explicit
  or already correct; rewriting them removes no bug.
