# コードレビュー

レビューは実際のユーザー体験と変更の安全性を優先する。

- 原則として、差分によって発生し、サポート対象の利用・運用、データ、セキュリティ・決済・認可、CI・本番ビルド、または明確なUX低下に影響する問題だけを指摘する。
- 仕様と呼び出し元を確認し、発生条件、到達経路、ユーザー影響、差分中の原因を示す。実行エラーは再現するか確実な根拠を示す。
- 要件・障害実績・既存テストに根拠のない境界ケースや非対応範囲は指摘しない。クライアントだけの異常入力への防御は、主要操作や永続化データに影響しない限り要求しない。
- ログ・通知は、主要操作の停止、データ消失、ユーザー影響のある障害の検知・復旧不能につながる欠落だけを対象にする。
- 再レビューの新規指摘は、直前の修正によるリグレッションか、新証拠のある重大問題に限る。却下済みの論点を新証拠なく蒸し返さない。

## レビューへの対応

- 指摘は機械的に修正せず、仕様、ユーザー影響、実装・保守コストから対応要否を判断する。メンテナーのコメントやリアクションも判断材料とする。
- 修正対象、解決済み、対象外、対応しないものに整理する。対応しない理由を説明し、修正または判断を終えたスレッドをResolveする。
