# フロントエンド設計

## 状態と責務

- 複数の表示領域やReact外の処理が使う状態はJotaiのatom、単一コンポーネントで完結する一時的UI状態はローカル状態に置く。複数atomの一貫した更新はwrite atomまたはドメイン関数にまとめる。
- 利用するコンポーネントが必要なatomを直接購読する。表示専用のview atomや転送だけのpropsは作らない。汎用表示部品へのpropsは許容する。
- derived atomは、ドメイン上の計算、購読範囲の縮小、readonly公開のために使う。
- 外部ライブラリの状態はそのライブラリを正本とし、atomとの接続は一箇所に限定する。必要な操作とスナップショットだけを公開し、業務上の分岐や複数領域の状態を集約しない。
- 状態の転記は外部ライブラリとの接続に限定し、アプリ内では直接参照やderived atomで表現する。
- 表示領域に閉じるライフサイクル処理はcustom hook、atom所有の処理はatom effectに置く。専用effectは`withAtomEffect`などで状態atomと一緒に公開する。
- `Provider`は複数インスタンスまたは独立したライフサイクルが必要な場合だけ使う。グローバルatomとの接続は最小限にし、単一インスタンスの一時状態は画面破棄時に初期化する。
- 実行中状態は操作と対象ごとに管理する。ローカル状態と同じ値のrefを重複保持せず、再マウントや複数の呼び出し元をまたぐ排他は操作境界のatomに置く。
- 永続化では省略による削除を反映し、文書全体の置換はtransactionまたはrevision照合で並行更新を検出する。

## 入力境界と検証

- 防御は信頼境界と実害に比例させる。画面固有の要件がなければ各数値入力で`NaN`や`Infinity`を個別に防御せず、永続化する値はサーバー境界で検証する。任意入力のパース失敗は扱う。
- 通常操作や正規の移行で生成されない不正形式・未知バージョンは読み取り境界で例外にし、専用の復旧UIを作らず共通エラー処理へ委ねる。
- 開発者が管理する設定値は必須値と型変換の確認に留める。権限やデータを損なわず利用箇所で明確に失敗する誤設定に、表記揺れまでの検証を加えない。
- 基盤が直接対応しない検証やキャンセルは、権限や他ユーザーのデータに影響しない限り、複雑なデータモデルや履歴操作で模倣せず、読み取り時の防御と復元経路で扱う。

## 機能ディレクトリ

- 状態、操作、effect、表示部品、外部hookとの接続は、扱う内容ごとにまとめる。`state`、`runtime`、`ui`やatomの種類で分けない。
- 独立して変更される振る舞いはファイルを分け、複数部品からなる領域は内容名のサブディレクトリにする。複数の内容を一つの状態・サービス・副作用ファイルへ集約しない。
