# UI スタイルガイド

## 配色と文字

- ブランドの基調色はSlateとする。通常の文字、アイコン、面に純黒を使わず、ロゴを有彩色へ変更しない。
- 通常本文はアプリケーションの本文色を継承する。`foreground`や`card-foreground`をコンテナ全体へ適用して、本文を不必要に濃くしない。
- `muted-foreground`は日時、件数、補足など、主操作に必須ではない情報に限定する。
- Blue、Redなどの有彩色は状態を伝える場合にのみ使い、ブランドカラーとして扱わない。
- 局所的な見え方を直すために、グローバルトークンや無関係な画面を一括で変更しない。

## 操作とフィードバック

- 作成と上書きのように結果が異なる操作は、別のラベルとボタンで明示する。
- 処理中と完了は、操作元が表示に残る場合はそのボタン内で伝える。完了時に操作元が閉じる場合は、遷移先のバナーやトーストで伝えてよい。
- 無効化は二重送信や競合を防ぐ範囲に限る。保存中も安全な入力は継続できるようにする。
- 保存中の追加入力は、保存開始時点の値との差分として未保存状態に残す。
- 実質的な変更がない状態をdirtyとして扱わず、破棄確認は失われる変更がある場合だけ表示する。
- 複数の入力要素で一つのフォームフィールドを構成する場合、検証エラーから先頭の編集可能要素へフォーカスできる契約を公開する。要素が空なら追加操作へフォーカスする。
- 内部IDやキーは、ユーザーが識別または操作する必要がない限り表示しない。

## 選択状態とモーション

- 選択状態は薄い背景色と控えめな境界で示し、太い枠、常時表示するring、装飾的なアニメーションを使わない。
- 選択によってスクロール位置を変えない。ただし、キーボード操作中の選択項目を可視範囲に保つ場合を除く。
- ボタン本体にscaleアニメーションを適用しない。状態表示の内容だけを短く切り替える。
- 頻繁に使う操作ほど動きを減らし、`prefers-reduced-motion`では位置移動とscaleを外す。

## 情報密度

- 繰り返し表示するカードは、識別に必要な情報と主要操作に絞る。説明や重複情報を常設して高さを増やさない。
